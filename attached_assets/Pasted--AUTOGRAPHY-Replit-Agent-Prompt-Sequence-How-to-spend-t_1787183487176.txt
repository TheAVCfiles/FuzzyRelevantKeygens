# AUTOGRAPHY — Replit Agent Prompt Sequence

## How to spend tokens

The agent burns most expensively when it is **inventing** — data, design decisions, architecture. It burns cheaply when it is **transcribing** a spec you already wrote. That's what this pack is for.

Rules:
1. Upload `00`–`02` and `/fixtures` to the Repl **before** the first prompt. Reference them by filename; never paste their contents into chat.
2. One prompt = one deliverable. Never "build the app."
3. Checkpoint after each step. If a step goes wrong, roll back rather than asking the agent to repair — repair costs more than redo.
4. Never ask the agent for design opinions. `02_DESIGN.md` is the answer.
5. Wire Gemini **last**. Build every screen against fixtures first so the demo is already shootable before a single API call exists.

---

## Step 0 — Scaffold

> Read `00_BRIEF.md` and `01_BUILD_SPEC.md`. Scaffold a Node + Express backend and a React frontend in one Repl, deployable to replit.app. Set up SQLite for state. Load everything in `/fixtures` into memory on boot and expose read-only endpoints: `GET /api/show`, `GET /api/flood`, `GET /api/context`, `GET /api/calls`. No UI yet. No AI yet. Confirm the endpoints return the fixture data unchanged.

## Step 1 — The credential clock

> Implement the Call model per `01_BUILD_SPEC.md` §1. Add `GET /api/call/active` returning the live Call plus a computed state: `LIVE` | `INERT` (no subject countersignature) | `DARK` (outside window). Add a ticking `seconds_remaining`. A Call without `subject_countersig` must always compute `INERT` regardless of its window. Write a test proving that.

## Step 2 — The Board

> Build route `/` per `01_BUILD_SPEC.md` §4 and `02_DESIGN.md`. Follow the design file exactly — palette, the four typefaces, the centered call-board layout, the tally warm-up. Implement the signature element: `--saturation` on `:root` driven by credential state, draining as the window closes and going fully sepia at expiry. Respect `prefers-reduced-motion`. One action button only.

## Step 3 — The Velvet Rope

> Implement the six policy rules in `01_BUildSPEC.md` §2 as pure functions in `policy/rope.js`. No AI, no network calls, no randomness. Each returns `{ pass, rule_id, reason, receipt_entry }`. Add `POST /api/evaluate` taking a proposed action and returning the first failure or a pass. Write tests using the four `inbound_requests` in `fixtures/calls.json` and assert each `expected_result`.

*This is the load-bearing step. Do not proceed until all four tests pass.*

## Step 4 — The Constellation (fixtures only)

> Build route `/constellation`. Render the flood from `fixtures/flood.json` as stars on `--house`, positioned by cluster and sized by engagement. For now, cluster by a hardcoded mapping — Gemini comes later. Tapping a star opens a panel with the raw signal and the coordination signals that classified it. Show **share of observed volume**, never a percentage of public opinion. Uncertainty renders as visible fog.

## Step 5 — The PR

> Build route `/pr/:id`. Three columns, equal weight, **Stay dark** leftmost. Each move shows its projected outcome and which context items it would cite. The sign action calls `POST /api/evaluate` first; on pass, it issues a Drop; on fail, it renders the refusal state per `02_DESIGN.md` — `HUMAN HOLD` in the system face, the rule that fired, and the line "Nothing was published." Add a **Not my look** action that closes the PR unmerged and writes a receipt.

## Step 6 — The Drop and the Seal

> Build route `/drop/:id`. Render the issued artifact: display-face title, every claim tagged with its `source_class`, the House Seal in `--brass`, edition number in mono. Compute a sha256 over the canonical drop payload. Build `/verify` — paste a drop id or hash, get `SEALED` with full scope detail, or `NOT IN REGISTRY`. Label all signatures as simulated.

## Step 7 — The Receipt

> Build route `/receipts`. Append-only log of every issue, evaluation, refusal, and expiry, in mono, rendered as closing credits. Include which rule fired on every refusal.

## Step 8 — Gemini + Agent Builder

> Wire the four Gemini calls in `01_BUILD_SPEC.md` §3 as a Google Cloud Agent Builder flow. Use `google-genai` (or `google-adk`). G1 reads the episode still and transcript multimodally. G2 clusters the flood and returns coordination signals. G3 reconciles clusters against the context repo to surface the authentic concern. G4 drafts the three moves. Replace the hardcoded clustering from Step 4 with G2 output. Every G-call writes its inputs and outputs to the receipt. **No G-call may write to the policy path.** Keep the fixture-backed path as a fallback so the demo never depends on a live API call.

## Step 9 — Ship

> Deploy to replit.app. Add a README documenting the architecture and where Google Cloud and Replit are used at runtime. Add an OSI license file (MIT) detectable in the repo About section. Confirm the repo is public.

## Guardrails to repeat if the agent drifts

- "The model never decides. If you are about to put a Gemini call in the policy path, stop."
- "Do not invent data. Everything comes from `/fixtures`."
- "Do not add a color. `02_DESIGN.md` has six."
- "Do not generate video or photorealistic likeness."
- "Never render a percentage of public opinion. Share of observed volume only."
- "Coordination is a likelihood with visible signals, never a finding."
